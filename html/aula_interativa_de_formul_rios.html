1. A Anatomia do Formulário e o Protocolo HTTP

O elemento <form> é o principal mecanismo para coletar informações do usuário e enviá-las para um servidor. O seu comportamento é ditado por três atributos fundamentais:

  • action: A URL (endpoint) que processará os dados da requisição. Se omitido, o navegador enviará os dados para a URL atual.
  • method: O verbo HTTP utilizado. Os mais comuns em formulários nativos são:
    • GET: Os dados são anexados à URL (Query String). Inseguro para dados sensíveis, limitado em tamanho e ideal para operações idempotentes (ex: buscas).
    • POST: Os dados são enviados no corpo (Body) da requisição HTTP. Usado para mutações de estado e envio de grandes volumes (ex: cadastro, upload).
  • enctype: Define como os dados serão codificados se o método for POST.
    • application/x-www-form-urlencoded: O padrão. Converte dados em pares chave=valor separados por &.
    • multipart/form-data: Fundamental para envio de arquivos. Quebra o payload em partes utilizando um boundary (delimitador).
<form action="/api/users" method="POST" enctype="multipart/form-data"> <!-- Inputs e botões aqui --> </form>

2. Semântica e Acessibilidade (a11y)

Um formulário não deve apenas ser visualmente agradável, mas compreensível para tecnologias assistivas (leitores de tela) e fácil de interagir em dispositivos móveis.

O Poder do <label>

A tag label conecta textualmente uma descrição a um campo. Ao clicar no label abaixo, observe que o foco é imediatamente transferido para o input. Isso é essencial para usabilidade (aumenta a área de clique, especialmente em checkboxes e rádios).

Agrupamento com <fieldset>

Para perguntas com múltiplas escolhas ou seções complexas, use `fieldset` e `legend`. Isso instrui os leitores de tela a anunciar o contexto antes das opções.

3. Validação Client-Side

Aviso de Engenharia de Software (Security-by-Design): Validações client-side (no navegador) existem estritamente para User Experience (UX). Elas reduzem requisições desnecessárias, mas nunca garantem segurança. Atacantes podem usar ferramentas como cURL ou DevTools para burlar o HTML. Todo dado deve ser validado novamente no Backend.

5. Exercício Prático: Clone do Buscador

O Google Search, na sua essência original, nada mais é do que um formulário HTML apontando para o servidor deles usando o método GET. Neste exercício, você criará um formulário funcional que pesquisa no Google.

Requisitos da Engenharia Reversa:

  • O action deve apontar para https://www.google.com/search
  • O method deve ser GET (para que a pesquisa vá para a URL).
  • O input de texto deve obrigatoriamente ter o atributo name="q" (é a variável que o servidor do Google espera receber: query).

Teste o formulário acima. Como usamos o target="_blank", sua pesquisa será aberta em uma nova aba e você poderá ver a query string (/?q=sua+pesquisa) na URL do Google.
